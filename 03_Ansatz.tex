\chapter{Ansatz}
\label{Ansatz}

In diesem Kapitel wird gezeigt, WIE man das im letzten Kapitel
ermittelten generellen Ziele realisieren bzw. wie man die allgemeine
Fragestellung der Arbeit beantworten kann. Bei konzeptionellen
Arbeiten erfolgt das in der Regel durch einen Software- oder
Softwarearchitekturentwurf. Diese Kapitel ist der wichtigste Teil in
der Arbeit – hier muss klar argumentiert werden und Alternativen
bewertet. Es muss eine systematische Herangehensweise demonstriert
werden. Entwurfsentscheidungen müssen begründet werden, so dass sie
nachvollziehbar sind.

Teil des Entwurfs ist die Klärung, was genau die Zielsetzungen /
Anforderungen an das zu erstellende oder konzipierende System bzw. die
zu erstellenden Prozesse sind. Die Anforderungen sin deine
Verfeinerung der generellen Ziele vor dem Hintergrund bekannter
Arbeiten, die man im Kapitel zuvor behandelt hat. Wie beim
Softwareengineering steht hier die Frage nach dem WAS im Mittelpunkt,
bevor man das WIE realisiert.

In der Regel beschreibt man den Entwurf Top-Down; es empfiehlt sich
oft, zunächst eine grundlegende Übersicht über das System zu
geben. Oft hilft dabei ein Architektur- oder Systemdiagramm. Im Rest
des Kapitels kann man Detailaspekte oder Use Cases beschreibt; wichtig
ist dabei immer, dass klar wird, inwiefern der Gesamtentwurf und seine
Einzelaspekte das gestellte Problem bzw. die gestellte Forschungsfrage
löst.
